## 要回答的問題

1. 「破綻 → 設局」會不會把戰鬥拖成解謎？
2. 沒看過設計的人能不能靠視覺線索自己發現設局？
3. 三段的長度與重試成本合不合理？

## 執行

需要 Godot 4.7。

```bash
godot --path prototypes/core
```

開啟後是開頭選單：**練習房**（MV-PROTO-001／002 的房間）、**Boss 戰**、**Boss 段落保留：關／開**。上下鍵或左搖桿選，攻擊鍵確認。

| 參數（放在 `--` 之後） | 作用 |
|---|---|
| `--boss` | 略過選單，直接進 Boss 戰 |
| `--tester <代號>` | 測試日誌的檔名代號（沒給用 `anon`；空白與斜線會換成底線） |
| `--boss-phase <1～4>` | 直接從第 n 段開打（4＝覺醒後的出口），只給 Brian 除錯 |

指定日誌代號的範例：

```bash
godot --path prototypes/core -- --tester brian
```

## Boss 戰

- **流程**：樹下篝火 → 走約 5 秒到 nance 樹（第 1 段；第一次進場有開場）→ 文字卡 → 小路（兩位老人跟著）→ 宮殿篝火 → 走約 5 秒到宮殿（第 2、3 段）→ 文字卡 → 宮殿另一端的出口。進場後身後的入口會關上。
- **規則**（若日後找外人測試，不要告訴對方）：近戰、招架、吹箭打斷前搖、射中光源的小光點都會累積下方的破綻條；滿了 Boss 硬直 4 秒、身上出現裂紋、光源爆亮，場上是希巴拉克時自動換成胡納普；這時胡納普的吹箭射中爆亮的光源＝設局成功，打掉一段血條。第 1 段假光閃耀時面向牠的人會白茫 2 秒。第 2、3 段胡納普斷臂（攻擊鍵無效，HUD 武器欄顯示「—」），希巴拉克是唯一能近戰的人。二段跳與讓工具自己動在戰鬥中停用，結尾覺醒後才能用。覺醒後畫面下方提示 6 秒「胡納普能二段跳了」（出口高台 550，單跳 400 上不去）。
- **死亡**：死在第 1 段回樹下篝火；死在第 2、3 段回宮殿篝火，從第 2 段重來。選單開啟「Boss 段落保留」時，死在第 3 段從第 3 段重來。回到篝火時血量與治療次數補滿；開場與文字卡不再重播。
- **文字卡**：至少顯示 1.2 秒才接受攻擊鍵（數值 `card_min_time`）。名稱依 [MV-NAME-001 名稱表](../../docs/design/MV-NAME-001_名稱表.md)；兩位老人的名字尚未定案，文字卡不寫名字。
- **數值**：`tuning/combat_tuning.gd` 的「Boss」群組（破綻量、硬直秒數、白茫秒數、各招的前搖與速度、三段的出招循環、召喚上限、反光柱數量）。調法同「調數值」。

## 測試日誌

每次進 Boss 戰（含展示模式）都會寫一份 `<代號>_<YYYYMMDD_HHMMSS>.jsonl`（每行一筆事件：開打、死亡與死因、白茫、破綻滿、微亮命中、設局、錯過硬直、通關／離開）。離開 Boss 戰時（通關、回選單或直接關掉遊戲）另寫同名 `.md` 摘要：總嘗試次數、每段的嘗試與累計時間、「超過 60 秒沒有進展」的區間（進展＝破綻滿、微亮命中、設局）、事件次數。F9 也會在主控台印出目前的摘要。「超過 60 秒沒有進展」的區間也會算進文字卡、小路、走到宮殿、覺醒後的出口、從死亡到重新開打（含離開座位）的時間，判讀時要對照 `.jsonl` 人工排除（Brian 2026-10-05 決定不修）。

位置：啟動 Boss 戰時主控台會印出 `BOSSLOG <資料夾>`；在 macOS 是 `~/Library/Application Support/Godot/app_userdata/MV Core｜核心原型/boss_logs/`。

## 調數值

1. 用 Godot 編輯器開啟 `prototypes/core`，按 F5 執行。
2. 編輯器左側場景面板切到「遠端」，選 `/root/Tune`，在檢查器展開 `data`，直接改數值，立即生效。
3. 調到滿意時在遊戲中按 F9：數值存回 `tuning/combat_tuning.tres`，主控台印出 Markdown 數值表。

初始值在 `tuning/combat_tuning.gd`；`.tres` 只存和初始值不同的數值。`max_hp`、`heal_charges`、敵人血量等生成時才讀取的數值，改完按 F10。Boss 的出招循環可以在檢查器改字串清單；打錯的招式名稱會被跳過。

## 自動驗證

```bash
godot --headless --fixed-fps 60 --quit-after 60000 --path prototypes/core -- --self-test
```

每項印一行 `SELFTEST PASS|FAIL`，最後 `SELFTEST SUMMARY`；有失敗時結束碼非 0。輸出中若出現 `SCRIPT ERROR` 也算失敗（Godot 遇到執行期錯誤會繼續跑）。機器人測試（探索區、低枝、出口高台、光束跳躍）以初始數值為前提，改了跑速、跳躍後可能需要重算地形。

## 上一個原型：MV-PROTO-002 換人與武器

> 規格：[todo/spec/MV-PROTO-002_換人與武器.md](../../todo/spec/MV-PROTO-002_換人與武器.md)

### 要回答的問題

1. 「換人＝換武器」的即時連段順不順？
2. 球具招架看不看得懂、抓不抓得到？
3. 兄弟的專屬能力讓探索「需要換人」但不煩？

### 兩兄弟與武器

- 場上一人，兩人共用一條血與治療次數；跑、跳、翻滾等基礎數值完全相同。
- 預設 Hunahpu（暖色）拿斧頭、Xbalanque（冷色）拿球具；左上角 HUD 顯示兩人（依名稱表寫成胡納普、希巴拉克）與各自的武器，場上的人亮色。
- 換人：自由狀態（地面或空中）、攻擊或招架的收招、翻滾結束後都能換；出招與判定中、翻滾中、治療中、受擊硬直中不能換（按下會在 0.1 秒內第一個能換的時候執行）。換完 0.3 秒內不能再換；換人沒有無敵。
- 斧頭：近距離弧形揮砍。掘棒：往前戳的長距離突刺（射程約 1.5 倍、判定窄、出招稍慢），傷害相同。
- 球具：側攻、上攻都是招架。按下後 0.2 秒是招架窗口，只擋正面；窗口內擋下**白色圓形**的攻擊 → 敵人硬直 1.2 秒、白色光環擴散，可以馬上換人或翻滾。**暗紫鋸齒**的攻擊擋不住。沒擋到會有 0.35 秒收招。球具空中下劈會彈跳，但不傷人。
- Hunahpu 能二段跳（落地或下劈彈起才恢復，空中換人不會刷新）。Xbalanque 的吹箭射中木障，他的工具會自己飛過去把木障砍碎。

### 房間

- **招架練習對象**：起點左邊、緊鄰左牆、頂上有木樁的那隻。不會動、不會死，每 2 秒出一次可招架的攻擊（前搖和爬行型一樣）；站在它面前 200 px 內會被打到。
- **戰鬥房、平台段**：同 MV-PROTO-001（見文末）。
- **探索區**：平台段右邊，一路往右到小戰鬥房（1 隻爬行型、1 隻飛行型）。中間有幾道帶斜紋的木障和高低差；不放提示，請自己找出過去的方法。掉進新的坑一樣扣 1 血、回坑邊。

### 要回答的問題

1. 以《Hollow Knight》為主、借《死亡細胞》的手感能不能成立？
2. 翻滾無敵與跳躍閃避的分工清不清楚？
3. 吹箭（低傷害、打斷）會不會架空近戰？

### 原有房間（戰鬥房、平台段）

- 左邊戰鬥房：爬行型 ×2（前搖白色圓形＝可招架）、飛行型 ×1（前搖暗紫鋸齒＝不可招架）。這一版沒有招架，兩種都靠翻滾或跳躍躲。
- 敵人前搖中用吹箭射中會被打斷（硬直）；同一隻 3 秒內不能再被打斷，頭上會出現暗色圓點。
- 右邊平台段：坑上方 3 個彈跳物（間距 500），要依序下劈彈過 3 顆才過得去，跳過任何一顆都會掉下去（自動測試用機器人驗證過，前提是初始數值；改了跑速、跳躍或彈跳速度後可能就不成立）。掉坑扣 1 血、回坑邊。敵人掉進坑會死。
- 兩個高台是單向平台：從下方可以跳穿、站上去。
- 下落：一般下落用 0.6 倍重力（比上升慢）；空中按下劈的瞬間，下落速度變回原本的 1.5 倍（Brian 2026-10-06 自評）。
- 飛行型只在你靠近牠的出生點（1000 px 內）時才會追，平台段不會被打擾。
- 攻擊、翻滾、跳躍都有 0.1 秒輸入緩衝：在還不能動作時按下（例如攻擊判定中按翻滾），會在第一個能動作的幀執行。
- 手把的上攻／下劈要把左搖桿推到六成以上，跑動中稍微偏上不會變成上攻。
