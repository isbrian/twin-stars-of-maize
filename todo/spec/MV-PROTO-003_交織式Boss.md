## 背景與目的

依 [原型驗證計畫](../../docs/design/MV-PROTO-000_原型驗證計畫.md) 第 3 節，回答三個問題：

1. 「破綻 → 設局」會不會把戰鬥拖成解謎？
2. 沒看過設計的人能不能靠視覺線索自己發現設局？
3. 三段的長度與重試成本合不合理？

上層依據：[MV-BOSS-001 Seven Macaw 設計](../../docs/design/MV-BOSS-001_SevenMacaw設計.md)（BOSS-1～9，本規格以它為準）；[VISION.md](../../VISION.md) 6.2、6.5；[討論紀錄](../../docs/design/MV-DESIGN-001_討論紀錄.md) 議題 C3、C5、C5-1、I3；[ART_SPEC.md](../../ART_SPEC.md) 第 5 節（戰鬥訊號）。

**不做**：美術、音樂、正式過場（以文字卡代替）、動物技能、聆聽、其他輔助選項（傷害調整、遊戲速度）。

### 定案（Brian，2026-10-05）

| 編號 | 問題 | 定案 | 理由 |
|---|---|---|---|
| PROTO3-1 | 範圍 | **一份規格、一次做完整場** | 問題 ③ 與驗收 ③ 只有整場量得到；外人不好約兩次 |
| PROTO3-2 | 分支 | **疊在 MV-PROTO-002 的分支上** | 換人、招架、吹箭都要用；002 自評後的修改再合進來 |
| PROTO3-3 | 兩項能力 | **戰鬥中停用，結尾覺醒後當場使用**（BOSS-9c） | 照正式遊戲；第 1 段「等他下來」的節奏不被二段跳改變 |
| PROTO3-4 | 進入方式 | **開頭選單：練習房／Boss 戰**，另保留 `--boss` | 外人可先熟悉操作；選單不提設局線索 |
| PROTO3-5 | 驗收 ②③ 的紀錄 | **程式自動寫測試日誌** | 「卡住超過 1 分鐘」與嘗試次數由程式算，Brian 只記原話 |
| PROTO3-6 | 出招順序 | **每段固定循環＋召喚為條件招** | 微亮每輪必出現，外人才有機會自己發現線索；讀招與重試公平 |
| PROTO3-7 | 實作方式 | **每招一個小腳本＋ Boss 主體**（主體只管段落、破綻、光源、循環） | 招式行為差異大，拆開好測、好調；不動一般敵人的 `enemy.gd` |

### 具體變更

#### 1. 破綻條（BOSS-5）

| 項目 | 規則 |
|---|---|
| 血條 | 三段，只能由設局打掉；近戰與吹箭不扣 Boss 的血 |
| 上限 | `gauge_max` 100 |
| 累積 | 近戰命中（傷害 > 0）+8；招架成功（含擋下擲出的果子）+15；吹箭打斷 Boss 的前搖 +10（同一隻 3 秒冷卻，沿用 PROTO1-5）；吹箭射中微亮光源 +12 |
| 不累積 | 打碎召喚出來的假光造物；破綻滿、硬直中的任何命中 |
| 滿了 | Boss 硬直 `boss_stagger_time` 4 秒，身上畫出裂紋，光源變最亮；場上是 Xbalanque 時**自動原地換成 Hunahpu**（不受換人冷卻限制，硬直結束後不換回） |
| 觸發 | 硬直中，Hunahpu 的吹箭射中最亮的光源 → 設局成功 → 打掉一段 |
| 錯過 | 硬直結束仍未觸發 → 破綻退回 50，Boss 恢復行動 |
| 吹箭打斷 | Boss 在可打斷的前搖中被飛鏢射中身體 → 該招取消、短暫硬直 0.6 秒。不可用射身體打斷的：假光閃耀、召喚，以及光束（光束只能射中眼睛的微亮來打斷，見第 3 節） |

#### 2. 光源與兩級亮度（BOSS-6-2b、2.2 節）

| 狀態 | 何時 | 飛鏢射中的效果 |
|---|---|---|
| 熄滅 | 平常 | 沒有效果（飛鏢穿過，打到 Boss 身體則照第 1 節） |
| 微亮 | 每段固定的時機（第 3 節） | 該招被打斷、破綻 +12、發出「微亮命中」 |
| 最亮 | 破綻滿、硬直中 | 能觸發設局的箭 → 設局成功；其他箭沒有效果 |

- 光源是只會被飛鏢打到的小判定框（新碰撞層），近戰打不到；位置隨段落：下顎、嘴（玉牙）、眼睛。
- 「能否觸發設局」在**發射時**決定：Hunahpu 射出的飛鏢才可以（同 MV-PROTO-002 木障的做法）。
- 微亮＝光源本身的小光點；最亮＝整個光源爆亮並向外放射；兩者要一眼分得出來。

#### 3. 三段的招式

出招循環（PROTO3-6；循環以字串清單放在參數檔，可調）。「召喚」只在場上沒有他召出的造物時出，否則跳過。

| 段 | 場地 | 光源 | 循環 |
|---|---|---|---|
| 1 | nance 樹 | 下顎 | 召喚 → 擲果 → 吃果子 → 擲果 → 吃果子 → 假光閃耀 → 俯衝（2026-10-06 手把試打後改：原本俯衝在第一次吃果子之後，假光閃耀後沒有立即的威脅） |
| 2 | 宮殿（斷臂後） | 玉牙 | 亂揮翅膀 → 哀嚎 → 撞寶座（接反光柱）→ 哀嚎 |
| 3 | 宮殿 | 眼睛 | 召喚 → 失衡撲擊 → 光束 → 失衡撲擊 → 光束 |

所有攻擊傷害 1；訊號依 ART_SPEC 第 5 節（可招架＝白色圓形，不可招架＝暗紫鋸齒）。

| 招式 | 前搖 | 行為 | 之後 |
|---|---|---|---|
| 擲果 | 0.6 秒，可招架 | 從樹冠朝玩家擲出一顆果子（拋射物，可招架；招架成功擊碎果子、破綻 +15） | 停在樹冠 |
| 吃果子 | — | 降到低枝吃 2.5 秒，**下顎微亮**；低枝是單跳上得去的平台 | 近戰空檔；微亮被射中 → 中斷、飛回樹冠 |
| 俯衝 | 0.7 秒，不可招架 | 斜衝向「前搖開始時玩家的位置」 | 落地喘 1.2 秒（近戰空檔），再飛回樹冠 |
| 假光閃耀 | 1.0 秒：展翅、全身聚光（不顯示圓形或鋸齒） | 閃光瞬間，**面向他的那一位**白茫 2 秒；背對就沒事（BOSS-6-2c） | 停在樹冠 |
| 召喚 | 0.6 秒 | 第 1 段：爬行型、飛行型各補到 1 隻；第 3 段：各補到 2 隻 | — |
| 亂揮翅膀 | 0.5 秒，可招架 | 先走到玩家身邊，再對身體周圍攻擊 0.6 秒 | 接下一招 |
| 哀嚎 | — | 捧著下顎 2.5 秒，**玉牙微亮** | 近戰空檔；微亮被射中 → 中斷 |
| 撞寶座 | 0.8 秒，不可招架 | 先移到「玩家在他與寶座之間」的位置，再高速衝向寶座；翻滾穿過或跳上兩側低台 | 撞上寶座 → 反光柱 |
| 反光柱 | 落點先亮 0.8 秒 | 3 道：一道落在玩家當時位置、兩道在固定位置；柱子持續 0.4 秒，不可招架 | 接下一招 |
| 失衡撲擊 | 0.6 秒，**可招架** | 撲向玩家 | 落地不穩 1.2 秒，近戰空檔 |
| 光束 | 蓄力 1.2 秒，**眼睛微亮**，不可招架 | 未被打斷：貼地的水平光束（離地 20～100 px）持續 0.5 秒，單跳跳得過 | 被打斷（射中微亮）：晃 1.0 秒，近戰空檔 |

**白茫**：只罩住畫面（不扣血）；0.3 秒淡入、1.4 秒維持、0.3 秒淡出，不閃爍。判定「面向」：角色面向那一側有 Boss（x 相同視為面向）。

**斷臂**（BOSS-2，第 2、3 段）：Hunahpu 的武器槽停用（攻擊鍵無效），吹箭、翻滾、跳躍、治療照常；Xbalanque 是唯一能近戰的人。

**場地亮度**（2.5 節）：每拔掉一個光源，場地的背景色暗一階；最暗一階時前搖訊號仍須清楚（以錄影檢查）。

#### 5. 流程與文字卡

```text
樹下篝火 → nance 樹（開場：吃果子示範下顎微亮）→ 第 1 段 ─設局→ 文字卡「斷臂」

→ 第 3 段 ─設局→ 文字卡「死亡」→ 文字卡「取回手臂、覺醒」→ 兩項能力解鎖 → 結尾出口 → 文字卡「通關」
```

| 環節 | 規則 |
|---|---|
| 開場（BOSS-9d） | 第一次進 nance 樹：Boss 降到低枝吃果子 3 秒、下顎微亮，玩家不能操作；接著飛回樹冠，名字與血條出現。重試時跳過 |

| 設局成功 | 清空召喚的造物 → 文字卡 → 下一段（換段時破綻歸 0、光源熄滅） |
| 結尾 | 「覺醒」文字卡後，Hunahpu 的武器槽恢復、二段跳與讓工具自己動解鎖；到達出口顯示「通關」並寫入日誌摘要 |

#### 6. 死亡與重試（BOSS-7b、C5-1）

| 死在 | 回到 | 預設從哪一段 | 開啟「Boss 段落保留」 |
|---|---|---|---|
| 第 1 段 | 樹下篝火 | 第 1 段 | 第 1 段 |
| 第 2 段 | 宮殿篝火 | 第 2 段 | 第 2 段 |
| 第 3 段 | 宮殿篝火 | 第 2 段 | 第 3 段 |

- 回到篝火：血量與治療次數補滿、召喚的造物清空、Boss 回到該段開頭、破綻歸 0。

- 「Boss 段落保留」在開頭選單切換，預設關；日誌記下開關狀態。

#### 7. 開頭選單、測試日誌、除錯鍵、數值

**開頭選單**：「練習房」「Boss 戰」兩個選項＋「Boss 段落保留：關／開」；上下鍵或搖桿選、攻擊鍵確認；不提任何設局線索。啟動參數：`--boss`（略過選單直接進 Boss 戰）、`--tester <代號>`（日誌檔名）、既有的 `--self-test`、`--demo*`。

**測試日誌**（PROTO3-5）：每次進 Boss 戰寫一份 `user://boss_logs/<代號>_<YYYYMMDD_HHMMSS>.jsonl`（沒給代號用 `anon`），每行一筆事件：

| 事件 | 欄位 |
|---|---|
| `attempt_start` | 段、段落保留開關 |
| `death` | 段、最後打中玩家的招式 |
| `whiteout` | 段 |
| `gauge_full` | 段 |
| `glow_hit` | 段、光源 |
| `setup` | 段 |
| `missed_window` | 段 |
| `clear`／`quit` | — |

離開 Boss 戰（通關、回選單或關閉遊戲）時另寫同名 `.md` 摘要：總嘗試次數、每段累計時間、「超過 60 秒沒有進展」的區間（起訖時間與當時的段；進展＝破綻滿、微亮命中、設局成功、換段）。摘要由純邏輯函式從事件清單算出；F9 也印出目前的摘要。

**除錯鍵**（測試時不告訴外人）：F10 重來目前的場地；F11 破綻直接加滿。

#### 8. 自動驗證（`--self-test`）

沿用 MV-PROTO-001／002 的格式。

| 類別 | 驗證內容 |
|---|---|
| 破綻條 | 各來源的加量；到上限觸發「滿」；錯過退回 50；硬直中的命中不累積 |
| 光源 | 熄滅時射中沒反應；微亮射中發出微亮命中並打斷該招；最亮時 Hunahpu 的箭觸發設局、Xbalanque 的箭沒有效果；近戰打不到；飛行中換人不影響已射出的箭 |
